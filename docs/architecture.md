# 架构与开发原则

## 围绕认识过程组织产品

慢慢看的主线是观察群体现象 → 拆解行业和分布 → 核对成员日线 → 保存观察与自己的想法 → 显式复看同一批成员；已有明确条件时继续筛选与历史研究。首页直接展示完整范围的描述性统计。筛选是用户形成明确问题之后的工具，不能要求用户先创建一组内部对象才开始观察。

## 一套日线事实，三种使用方式

- `kan/core/streaks.py` 与 `swings.py` 负责连续段和确认波段的唯一算法。
- `kan/service/market_study.py` 负责市场交易日对齐、价格校验、指标与历史事件；`trend_search.prepare_cached_history` 负责读取并裁切同一基准的行情。
- `discovery.py` 一次逐股读取，聚合当前分布、行业剖面、相邻等长窗口迁移与固定成员轨迹；所有完整范围成员和缺口都返回。
- `trend_search.py` 判断用户明确条件，只计算当前匹配及可选两日对照；不自动建立历史研究。
- 历史研究明确执行后才计算事件并保存当次证据，和观察/筛选复用相同指标。

Web、TUI、CLI、Python 与 MCP 是薄适配器。前端可排序、搜索和按后端分组键下钻，不重新计算金融指标。数据聚合用确定性统计与事实短句，不增加 LLM 解释服务、综合评分、后台扫描平台或第二套缓存。

## 统计分母是契约

当前分布采用本窗口完整成员。相邻窗口变化只采用两个窗口都完整的同一批成员。历史轨迹采用每个点都完整的固定成员，不能用每天不同成员的比例制造扩散或收缩。三者分别暴露分母与缺口。

缺市场交易日不压缩、不补零；旧数据不静默代替请求日期。当前上市名单和行业归属的回溯明确标注，不能冒充历史时点名单。中位数与分位数不等于行业指数、成交收益或未来概率。

TuShare 单股与全市场都从原始日线及复权因子按统一截止因子物化窗口。缺少基准证据的缓存不可读，显式刷新后原子替换；失败不覆盖已有有效数据。分布桶只在精确边界消除计算尾差，不四舍五入原始涨跌方向。

## 用户状态与任务

SQLite 保存自选/候选、笔记、持仓、命名筛选、研究定义和运行索引。观察记录复用workspace_state按记录独立保存，列表只有轻量摘要；原成员事实与用户文字不被复看改写，复看冻结代码与窗口并共用同组比较函数。研究目录中的 Parquet 保存当次价格、全部事件及形态参照。图证读取冻结研究事实；普通观察详情读取所选截止日的当前缓存，并明确说明。

个人池服务只管理成员、来源与笔记，不重复读取行情或计算另一套涨跌。行情更新复用现有持久任务，范围明确为全市场、个人池或指定代码。旧 Screen/AI plan/ScreenRun 工作流和专属任务已删除，用户已有 SQLite 原始记录保留；独立 OHLC 查询通过 `kan ohlc` 提供。

## 边界校验与错误传播

Pydantic 在 HTTP/CLI/MCP 输入边界校验参数。日期、价格合法性、复权与缺失语义在外部数据进入计算时校验。已定义的内部对象直接使用其字段，不为旧测试入口查找动态实现或提供兼容默认值。

单股无行情、缺列或重复日期保留为该股资料缺口；程序错误不吞成空成功结果。持仓接口不能把失败伪装成空账户。更新采用原子写入保护真实数据，已有凭据和用户资产不随代码删除而销毁。短刷新先扩展到已有历史起点，最终写入再次核对有效日期包含关系；不同基准的qfq不拼接。网页设置沿用CLI的有效配置与校验，空白保留，环境变量生效时不写无效覆盖。

## 开发与验证

先跑受影响计算或用户路径。群体统计用可手算样本守护分母、窗口、缺口与边界；一次完整流程确认观察→行业→分组→成员证据。真实历史数据可用独立公式核对，不能把模拟或旧数据冒充当前事实。

CI 在 Linux 执行一次类型、Web 构建、功能回归、安装和真实终端行为验证；macOS/Windows 做干净安装。发布保留代表性平台、Python 与安装器组合，复用安装脚本。终端检查关注反馈、JSON 分流与退出恢复，不以毫秒竞赛或固定文案作为功能契约。

不设硬覆盖率、命令数量、源码结构或固定角色门禁。仅有新的故障或未覆盖风险时增加测试；依赖与实现变更后跑对应检查，已通过的检查不机械重复。性能结论需要同条件基线，单次耗时不冒充提升。
