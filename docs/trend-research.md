# 市场观察、趋势筛选与研究验证

## 先观察群体变化

市场观察把完整范围的日线加工为分布、行业剖面、前后窗口变化与固定成员轨迹。默认窗口20个市场交易日；Web可选5/20/60，CLI/HTTP支持2–120。窗口定义可见的描述尺度，不生成筛选条件、评分、推荐顺序或候选状态。

本窗口为截止日相对N个交易日前的收盘变化，前窗口紧邻本窗口，同为N个交易日。两段共用一个边界收盘，需要2N+1个完整交易日日线；本段自身只需要N+1个。价格来自同一复权基准，区间变化按端点比值计算，不相加日涨跌百分比。

| 观察 | 实际口径 |
|---|---|
| 当前分布 | 本窗口完整成员中涨/跌/平数量、上涨占比、中位数与第25/75分位；缺失单列 |
| 两段对照 | 仅两段均完整的同一批成员；分别计算两段上涨占比与中位数，上涨占比差用百分点 |
| 方向迁移 | 两段均上涨、前跌本涨、前涨本跌、两段均下跌、至少一段持平、资料不足；不称已反转或趋势确认 |
| 历史轨迹 | 最近N个截止日分别计算滚动N日收益；整条轨迹使用每一点都完整的固定成员，避免成员变化制造趋势 |
| 行业剖面 | 用本次相同行业归属拆开范围，再按完全相同公式聚合；不能把成员中位数当行业指数 |

分布桶覆盖负10%以下、负10%至负5%、负5%至0%、持平、0%至5%、5%至10%、10%以上，精确开闭边界随标签返回。成员返回同一个`distribution_bin`，下钻直接按该键过滤；前端不重算金融口径。每个桶和变化分组可追到本次完整成员，按代码排列。

当前分布、两段对照与历史轨迹分母可能不同，分别显示。空范围、历史不足、缺日、缺缓存都不会生成零收益或虚构趋势。未取得当前日期行情时保留真实截止日，显示本地主要数据日；用户点击后才切换。

`DiscoveryQuery → discover_market → DiscoveryResult`由Web、CLI `kan discover`、Python与MCP `kan_discover`共用，HTTP为`POST /api/v1/discovery`。查询只计算事实，不建立后台任务或保存研究。图证读取所选截止日的当前本地缓存；需要保留当次事实时，显式创建历史研究。


## 保留认识，并复看同一群体

在市场事实之后记下整个范围的观察，或在行业剖面旁保存该行业。记录保存明确截止日、完整范围、当时成员收益与缺口、群体统计和用户自己的文字。保存时服务重新核对固定日期及已展示事实的内容版本；成员或行情已变化则不写入，保留草稿，明确查看新事实并核对后再保存。不接受浏览器提交的统计。没有可判断成员时先准备数据，不保存纯缺口。记录沿用SQLite状态，不建立任务、定时执行或候选状态。

“我的研究”同时显示观察记录与条件研究。读取观察与编辑文字只读写存档，不取行情。显式复看冻结原成员代码和窗口，不重新解析当前行业或个人池；新增股票、行业变更不会改变原范围。按原/新两个滚动窗口都完整的同一批成员比较上涨占比、中位数与方向迁移，其他成员单列未知。两个窗口可能重叠，比较不等于持有收益。复看不覆盖原日期、原事实与想法；同日复核可检查当前缓存修正，早于原日则拒绝。

复看中的方向迁移可下钻对应成员，并切换原观察与本次日期核对日线。分组比较两次观察的收益，不使用本次相邻窗口的迁移标签；图证读取当前本地行情，原记录未冻结逐日日线，资料修订可能使图中变化与存档统计不同。

HTTP入口为`/api/v1/observations`及`/{id}/review`；CLI为`kan observe save request.json`、`list`、`show <id>`、`review <id> --as-of YYYY-MM-DD`。保存已浏览的结果时，将对应组的`fingerprint`作为`expected_fingerprint`传入；冲突返回HTTP 409 `observation_changed`，不能去掉版本字段重试来绕过。未提供版本的CLI/Python调用表示按明确查询在保存时新建观察。保存输入的`query.as_of`必须明确，`kan observe schema`输出完整契约。MCP `kan_observe` 的`action`为`save/list/show/review`，保存只在用户明确要求时执行。

## 从缺数据回到原观察

缺少来源或行情时可进入数据准备，保留原范围、代码、行业、截止日和窗口。数据页配置仅写用户本次填写的字段，空白保留已有配置；环境变量生效时页面如实显示来源，不写入无法生效的文件覆盖。配置认证材料不在回包或参数校验错误中回显；来源错误经过脱敏，TuShare错误还精确移除本次请求token。

发现页汇总成员无法判断的实际原因，区分未获取、文件无法读取、空日线与明确标记的原价／因子冲突。已有文件不等于可参与统计；应先核对原因，更新任务完成后再看实际可判断范围。

准备计划用真实市场交易日计算覆盖本次相邻两个窗口所需的范围，历史观察还计入该日期到当前的交易日跨度；不把自然日当交易日。行业转成明确代码范围，不无声扩大取数。超过现有补数能力时在运行前说明；任务完成或部分完成后显式返回原观察重算，缺口仍由真实结果决定。

短请求不会截断已有较长的有效行情。数据层扩展请求起点，整段重新生成同一复权基准；新响应缺少已有有效交易日时失败并保留原文件，不直接拼接qfq。未核实复权口径的缓存仍保护其有效日期范围，旧价格不参与计算或拼接。任务错误保留来源的脱敏原因。

截止日的复权因子独立于该日是否有成交日线。原始截面保留仅含因子的行用于确定分母，派生日线只输出真实报价，不补价、不用最后已知因子代替截止日因子；没有截止日报价的成员仍按未知处理。真实报价的因子缺失或非法时保留原始证据，复权价格置空，交由原有校验报告无效原因。旧原始缓存仅补齐本次截止日的因子响应，保留旧报价字段，不强制重抓整个历史窗口。

## 从一个明确问题开始

`kan web` 默认打开市场观察，趋势筛选位于 `/explore`。选择连续上涨、连续下跌、先跌后涨、先涨后跌、区间涨跌天数、波段结构或形态检索，明确填写参数后才执行。初始没有天数、筛选策略或股票推荐，允许显式浏览整个股票池。

当前筛选计算指定截止日的匹配和图证，可显式对照另一个交易日；不生成 Study，也不计算历史事件。结果表格、地图、连续段、本段变化和多周期位置使用同一份事实。先选行业时，先缩小完整股票范围，再逐股判断，不只保留恰好有数据或匹配的对象。

| 条件 | 精确含义 |
|---|---|
| 连续收盘上涨 / 下跌 | 连续市场交易日收盘严格高于 / 低于前收；平盘与缺行中断 |
| 连续阳线 / 阴线 | 收盘严格高于 / 低于当日开盘；十字线与缺行中断 |
| 先跌后涨 / 先涨后跌 | 当前段与紧邻前一相反段分别符合天数条件，不跨平盘或缺口寻找更早一段 |
| 最近 N 日上涨 / 下跌次数 | 最近 N 个市场交易日逐日收盘变化的计数，需 N+1 个完整收盘，平盘不计；可以查询零次 |
| 至少 / 恰好 / 最多 N 天 | 连续段“最多”是 1–N 天，不包含反方向的零天 |

数据窗口开头或缺口之后的连续段可能只有下界；显示“至少”，不能据此断言恰好或最多。方向判定使用原始数值，不先四舍五入；本段价格变化使用端点比值，不把每日百分比相加。

## 波段结构与趋势因子

波段按窗口内的**收盘价**识别，不使用盘中高低价猜测转折。选择上升、下降或混合结构，填写观察窗口后执行；可叠加当前波段方向、斜率、效率或阳阴线条件。所有参数随保存筛选、两日对照与历史研究传递。

| 字段 | 口径 |
|---|---|
| `bull_count` / `bear_count` | 最近 N 根完整日线中的阳线/阴线根数，分别为收盘高于/低于开盘，十字线不计 |
| `candle_balance` | 同窗口阳线根数减阴线根数；`> 0` 精确表示阳线多于阴线，不等同于至少半数天上涨 |
| `return_pct` | 最新收盘相对 N 个市场交易日前收盘的变化百分比，需 N+1 个收盘 |
| `trend_slope` | 最近 N 次变化、N+1 个收盘的对数价格最小二乘斜率；以 `100 × expm1(斜率)` 转换为 `%/交易日`，不是端点收益除天数 |
| `trend_efficiency` | 同窗口首尾收盘净位移绝对值 / 逐日收盘位移绝对值之和，范围0–1；全程平价为0，不表示未来胜率 |
| `swing_structure` | 最近 N 根收盘内，最近两组已确认波峰与波谷均抬高为1、均降低为-1、关系混合为0；不足两组为未知 |
| `swing_direction` | 当前阈值段上行为1、下行为-1，窗口尚未形成方向为0；小于反转阈值的折返不立即切段 |
| `swing_count` | 窗口内相邻已确认转折点之间的完成段数；首段边界锚点和最新未完成段不计 |

`swing_reversal_pct` 控制确认转折所需的反向幅度，默认5%，范围大于0且小于100；这是显式可调的计算口径，不会自动添加筛选条件。上行从运行收盘高点回落达到阈值时确认波峰；下行从运行收盘低点回升达到阈值时确认波谷。数值比较使用相对 `1e-12`、绝对0的误差容差，仅消除复权运算尾差，不是额外价格幅度参数。相同极值保留最后一次出现日期。首段只建立方向，不把窗口边界当作真实转折点。

每个转折点同时展示发生日期和 `confirmed_at`，确认只使用当日及之前的数据。当前未完成段单独表示；窗口不变、仅追加未来行情时，之前已经确认的点不会改写。**滚动窗口改变起点后，边界附近的识别结果可能变化**，这不等于在旧截止日使用未来数据。

已确认点的结构与当前价格分开解释。若历史确认点仍抬高、当前收盘却已低于最近确认波谷，`structure_broken=true`；下降结构中当前收盘高于最近确认波峰时对称处理。它只描述截止日是否越过最近结构边界，不等于预测反转，也不追记一次已经收复的历史越界。混合或结构不足时此字段为空。

完整窗口有数据、但确认峰谷不足，仍归为“无法判断结构”，不能冒充混合结构或承诺更新行情即可解决。缺行不压缩交易日、不填零。不同观察窗口和反转幅度描述不同尺度，不存在通用最优参数；15根日线不保证足够形成两组峰谷。

例如，明确查询“最近15根K线阳多于阴，并且15交易日净上涨”：

```bash
kan trend --universe all --window 15 --bull-excess 0 --return-above 0
kan trend --universe all --swing up --window 60 --reversal-pct 5
kan trend --universe all --swing down --window 60 --reversal-pct 3 --compare-to previous_session
```

第二条只筛已确认上升结构，当前段可能向上也可能向下；若还要求方向，使用Web附加“当前波段方向”条件或typed API/MCP。图中实线连接确认点，虚线标出当前未完成段；逐点表保留确认日期。当前图证和历史事件图证调用同一识别函数，历史图证截断到事件日期后计算。

## 两日变化与具体原因

`compare_to` 默认为空；可显式设为 `previous_session` 或早于截止日的完整交易日期。上一交易日来自市场日历，不是减去一个自然日。对照日与截止日使用本次相同的完整股票范围、行业归属、条件和复权基准，逐股只读取一次缓存。

| 变化 | 对照日 | 截止日 |
|---|---|---|
| 新出现 | 明确不满足 | 满足 |
| 持续匹配 | 满足 | 满足 |
| 已退出 | 满足 | 明确不满足 |
| 无法确认 | 任意一端资料不足 | 不归因成新增或退出 |

双日均明确不满足计入 `unchanged`，不占变化列表；形态参照的自身窗口单列 `excluded`。`comparable = entered + continued + exited + unchanged`，加上 `uncertain` 和 `excluded` 等于原完整范围。当前匹配与当前缺口仍由原 `coverage` 描述，不能拿两日的未知数量替换它。

变化行保留两日每个条件的实际值、精确/下界状态、是否满足和原因。图证请求的 `at` 只接受本次截止日或对照日，价格序列截到所选日期；某一端没有有效日线时明确说明，另一端仍可查看。当前筛选不会因为开启对照而保存 Study 或生成历史事件。

固定形态参照晚于对照日时，比较属于事后形态检索；参照仍按原明确日期使用，不能偷偷换成对照日形态。两日价格共用当前缓存的统一复权基准，而非两次运行各自保存的报价。

## 同一结果的地图与位置

地图只展示当前匹配对象；选择截止日、位置窗口与涨跌窗口后，所有可绘制对象使用同一日期。横轴是收盘在最近 N 日最高/最低价之间的位置，纵轴是相对 N 个市场交易日前收盘的涨跌。

常用位置窗口为 30/60/180 日，涨跌窗口为 5/20/60 日，同次结果返回，切换显示不重新扫描全市场。短期条件可能可判断而长期位置缺失，地图单独标明可定位对象，不把长期缺口变成条件失败。

缺少完整窗口、截止日行情或本地缓存的股票计入缺口；不会用另一日期的数据代入，也不会填成 0。当前 A 股身份来自当前上市名单，行业归属也是当前口径。

TuShare 日线使用原始 `daily` 与 `adj_factor`，同一股票的整个窗口按同一截止日因子计算复权价格。旧的逐日 qfq 拼接缓存缺少统一基准，不继续读取；显式更新行情后重建，已有研究、持仓和凭据不会因此删除。

## 圈定区域，形成研究

桌面可以显式进入框选模式；手机或键盘用户可以直接在附加条件中填写位置与区间涨跌上下界。选区回填成可见条件，点击筛选后才更新结果。核对历史时使用原完整范围，不把当前匹配对象误当历史股票池。

默认不建立条件组合。条件字段、窗口、比较符和数值必须明确，全部条件按 AND 组合。`kan study catalog` 给出实时字段与定义，`kan study schema` 给出完整输入契约。

位置与收益来自同一 `calculate_metrics`；前端不通过自己的公式重新判断匹配。

## 按需核对历史

![研究条件、事件日线与逐项证据](assets/research-evidence.png)

点击“核对历史”后确认回看范围、事件采样和后续窗口，再执行并保存。历史研究与当前筛选共用指标，运行后取得：

- 指定截止日的当前匹配，以及因资料不足无法判断的对象。
- 历史股票日的可用、可评估与原始命中数量。
- 按首次满足、每次满足或不重叠规则选出的事件。
- 事件后观察窗口完整、尚未成熟、应有行情缺失三类数量。
- 完整样本的实际涨跌分布、分位与逐事件证据。

“首次满足”需要前一个市场交易日明确不满足；缺行后不能凭空断言出现了一次新事件。连续段在数据开头或缺口后可能只知道长度下界，此时不能据此断言“恰好 N 天”。

后续窗口按市场交易日定位，停牌或缓存缺行不会被压缩成连续行情日。完整统计基于全部事件；列表分页不会改变统计分母。

## 形态检索

参照来自用户明确选择的股票、日期与窗口。每段收盘序列按首日归一到 100，形态距离为对应各日差的均方根，单位是百分点。阈值由用户填写，不内置“最好股票”评分。

参照窗口与候选窗口都必须完整。同股票、同日期的自匹配单列排除。参照行情随运行保存，图证不会受到之后缓存刷新的影响。

如果参照形态晚于历史事件，这是一种事后形态检索：可描述“过去哪些形状相近、后来怎样”，不能证明当时可以提前选择它们，也不能称为策略回测。

## 保存与继续研究

“保存筛选”只保存名称与查询，载入后可以继续修改或重新筛当前，不读取行情或创建历史研究。研究执行后才自动留存定义和结果。SQLite 存轻量状态、摘要、索引与参照，命中对象的当次行情和完整事件放在独立 Parquet 中。点击历史样本读取当次事实，不读取新缓存冒充旧结果。

固定日期的研究可“按原日期复算”。“更新至最近收盘”是显式改变截止日的动作，保持条件与形态参照，保存新运行并比较当前命中新增、移出和数据不可用。数据丢失不会被解释为不再符合条件。

```bash
kan trend --universe all --down-days 5 --format json
kan trend --universe all --up-days 3 --comparison eq
kan trend --universe all --up-days 2 --previous-down-days 3
kan trend --universe all --rising-days 8 --window 10
kan study run query.json --format json
kan study list --format json
kan study show <study_id> --format json
kan study rerun <study_id> --latest --format json
```

## 数据更新与入口

数据页支持明确的全市场、个人池或代码范围更新。获取日数与本次研究需要的历史窗口应匹配；代码更新不会扩大成全市场，个人池包括已有自选、持仓与人工候选。任务状态、部分失败和数据缺口保持可见。

Web 当前入口为市场观察、趋势筛选、研究记录和数据工具；当前结果提供保存筛选、形态检索与显式历史研究。请求日期无可判断行情时，分别显示缺口和本地主要数据日期；只有点击对应按钮才改日期，不静默回退。

TUI 可直接填条件、范围与截止日期，Enter 或 Ctrl+Enter 执行；`f` 编辑、`m` 看缺口、Enter 查日线、`s` 保存、`g` 载入、`h` 配置并核对历史。`d` 明确切到本地主要数据日，`c` 查看两日变化，变化详情中 `1/2` 查看截止日/对照日日线；`l` 查看研究，研究内 `1/2` 切换当前/历史，`n/p` 翻页，Esc 返回。带日期或前后段的已存条件可继续编辑；简易表单无法完整表达的附加条件会保留并锁定，只有明确新建才重置。

HTTP 当前接口由 `/api/v1/openapi.json` 描述，当前筛选为 `/trends/search`、`/trends/search/evidence`、`/trends/saved`；历史为 `/studies` 系列。MCP `kan_trend` 与 Python `search_trends` 直接使用同一 Query/Result。旧 CLI 参数与旧页面不保留兼容别名；已有用户数据与凭据不会因页面移除而删除。

## 解释边界

当前上市名单的历史分析是当前股票池回溯，不能冒充历史全市场。来源日线的复权处理和本次输入序列随结果标注；相对指标在同一输入中计算。价格分布不是成交收益，样本上涨占比不是未来概率。当前不支持分钟事件；缺失分钟不能用日线猜测。
