## 1. 项目简介

慢慢看（manmankan）是一个面向个人散户的 A 股自选股 CLI 工具，命令入口为 `kan`。
核心定位是 **"看清你的股票正站在历史价格的哪个位置"**——不预测、不推荐、不做买卖建议，
只把 N 日窗口内的最高/最低价折算成 0–100% 的位置数字摆给用户看，让用户自己判断。

围绕这个定位提供四类命令：

- **位置扫描**：`kan scan` 全景扫描自选股在 3/5/7/10/15/30/60/90/120/180 日多周期的位置，
  自动高亮多周期共振（同一只股票在多个周期都触及阈值）。
- **筛选模式**：`kan low N` / `kan high N` 一次性筛出"近 N 日处于低位/高位"的标的。
- **连续涨跌看板**：`kan trend` 看自选股近 N 天的连续涨跌情况，支持阳/阴线口径。
- **单只详情 + 自选管理**：`kan info`、`kan add/remove/list/import/clear/uninstall`、
  `kan completion install`、`kan fetch`。

数据来源采用多源 K 线 fallback：`baostock → 新浪 → 东财 → 腾讯`。
本地 Parquet 缓存（XDG 规范路径 `~/.local/share/kan/`），不上传任何数据，不做任何账户绑定。

设计哲学三条：
- **位置感优先于预测**。展示事实位置，让用户自行判断，避免出现"建议"。
- **离线友好**。一次拉取，本地缓存，再次使用 `kan scan` 不用等网络。
- **隐私优先**。watchlist、缓存、快照全部本地存储，软件本身不需要登录。

## 2. 关键技术决策

### 2.1 数据源策略：多源 fallback

**决策**：不依赖单一数据源，按可靠性排序 `baostock → 新浪 → 东财 → 腾讯`，
任意源成功即返回，全部失败抛异常。

**原因**：
- 东方财富 `push2his` 实测对部分 IP 段（家庭宽带 / 部分 VPN 段）持续封禁，
  非临时性失败，retry 无效（akshare 上游 issue 已确认）。
- baostock 走独立服务器，免熔断、稳定，但接口慢一点。
- 新浪 akshare 路径免登录、精度高，作为第二备份。
- 腾讯只作为最后兜底，且其 amount/volume 字段语义跨板块不一致，
  在 normalize 层主动 drop。

### 2.2 长 watchlist 并发拉取

**决策**：`fetch_batch` 用 `ThreadPoolExecutor`（默认并发 5）+ `rich.Progress` 进度条，
失败累积末尾汇总展示。

**原因**：
- 串行拉取 100+ 只自选股可能阻塞数分钟无任何反馈，体验不可接受。
- 并发 5 在大多数家庭网络下不会触发上游限流，平均耗时 30–90 秒。
- 进度条只在 TTY 环境渲染，pipe / 重定向时静默，符合 Unix 工具习惯。

### 2.3 跨板块 amount 字段语义对齐

**决策**：腾讯源返回的 `amount` 字段在 normalize 层主动 drop，让下游统一填 NaN。

**原因**：
- 腾讯 `stock_zh_a_hist_tx` 的 `amount` 字段在主板/创业板等于"成交手数"
  （volume/100），而科创板（688/689）等于"成交股数"（1:1）。
  按 `×100` 反推会把科创板放大 100 倍。
- manmankan 只支持 A 股，跨板块语义不可移植 → drop 比 board-aware 转换更安全。
- `tests/test_normalize_alignment.py` 10 条三源一致性测试守护语义对齐。

### 2.4 命令行框架：typer + rich

**决策**：CLI 用 typer 做命令路由 + 类型注解参数声明；输出用 rich 的 Console / Table。

**原因**：
- typer 基于 click 但对类型注解 first-class 支持，参数校验代码量很小。
- rich.Table 自带终端宽度自适应能力，配合自定义的 `responsive_periods`
  可以做到 130 列显示 10 周期、80 列退化为 4 周期，共振列始终可见。
- rich.Progress / Spinner 在 TTY 环境下自动渲染，pipe / 重定向时静默。

### 2.5 数据存储：XDG 标准路径 + parquet

**决策**：watchlist 用 JSON，K 线缓存用 Parquet，全部放在 `$XDG_DATA_HOME/kan/`
（默认 `~/.local/share/kan/`）。

**原因**：
- XDG 规范是 Linux/macOS 的事实标准，避免在 home 顶层制造一堆点目录。
- Parquet 列式存储，单股 K 线压缩后比 CSV 小 5–10 倍，pandas 读取也快。
- 不引入 SQLite——单机工具没有并发写需求，parquet 直读已够。

### 2.6 Shell completion：自动安装

**决策**：任意 `kan` 命令首次启动自动检测当前 shell 并安装补全，
通过 `KAN_NO_COMPLETION_AUTOINSTALL=1` 关闭，非 TTY 环境跳过。

**原因**：
- 用户视角："装完即用"是基础体验，不应让用户专门跑一条
  `kan completion install` 才能用 tab 补全。
- 默认值符合最低成本路径：自动装、装完静默、不打扰；
  极少数不喜欢的人通过环境变量退出。
- 同时保留 `kan completion install [shell]` 显式命令，便于用户手动重装、
  切换 shell 时复用。

### 2.7 隐私优先：本地存储 + 不上传

**决策**：watchlist、缓存、扫描快照全部存本地，软件本身不需要任何账号、
不做任何数据上传，对数据源（akshare 等）的请求也不带任何用户标识。

**原因**：
- 自选股是高度个人化的信息（暗示持仓 / 关注方向），用户合理预期是不离开本机。
- akshare 官方声明数据"仅限学术研究"，本工具继承此限制——
  不做商业化、不构建用户画像、不做 SaaS。
- 配套 `scripts/check-privacy-leaks.sh`（禁用词扫描）+ `.githooks/pre-commit`
  保证项目本身的公开档案不会泄漏维护者的内部语境。

## 3. 这一版的不足（坦诚的）

1. **并发控制粒度太粗**。`fetch_batch` 用线程池写死默认并发 5，对 200+ 只 watchlist
   还是偏慢；对 50 只以下又有点浪费。需要按 watchlist 规模动态调，或加用户可配置项。

2. **K 线源切换没有人工 override**。当前只能按 fallback 链路顺序自动切，
   用户没法说"我家网络上 baostock 慢，强制走新浪"。
   `kan doctor` + `--source` 选项已列入下一批 patch（路线图 TD-3）。

3. **熔断器在进程内**，每次启动重置。如果某个源连续被 ban，下一次跑 `kan scan`
   还是会先去敲它再 fail。需要落地 `circuit.json` 持久化（5min down TTL / 1d ok TTL）。

4. **测试覆盖率约 60–70%**（164 个测试）。覆盖了核心算法、watchlist 操作、
   多源一致性、CLI 表面，但**真终端 TTY 渲染**层（spinner / Progress / Live Display）
   没法在 pytest 里跑，全靠手测。长期需要补 pty 测试。

5. **长 watchlist 体验仍待优化**。已加并发 + 进度条，但 200 只以上的 watchlist
   首次冷启动仍要 1–2 分钟，且失败累积只在最后展示。可以考虑分批结果增量输出。

6. **`amount` 字段在腾讯源被 drop**，意味着启用腾讯兜底时成交额相关的衍生分析
   会缺数据。已知技术债，路线图 TD-1 计划在 parquet 加 `_source` 列，
   下游分析按源决定是否信任 amount/volume。

7. **macOS 系统代理 / TUN 模式 / 公司网关**没有诊断手段。当三源全 fail 时，
   用户拿到的是一坨堆叠 traceback，没法快速定位是网络问题还是源问题。
   `kan doctor` 设计文档已写（`docs/design-kan-doctor.md`），下一批 patch 实现。

## 4. 设计原则（给未来的自己和贡献者）

### 4.1 1.0 = 对外 API 稳定承诺

semver 1.0 不是版本号大就打的，是对 API 稳定性的对外承诺。
应等真实用户反馈跑过至少一个完整循环再考虑。
**重大决定（首个 stable 版本号、breaking change、license 选择）
必须等到至少一个完整的"自己使用 + 外部反馈"循环之后再做。**

### 4.2 TTY 真实测试不可省

`spinner` / `Progress` / `Live Display` 这类组件在 pipe、非 TTY、CI 环境下会
**静默不渲染**。pytest 里 capture stdout 跑断言看上去全绿，真终端跑起来
spinner 转都没转一下。原则：**含动态终端渲染的改动必须用真终端跑一遍 `script(1)`
或 pty 包装的测试**，不能只靠管道断言。

### 4.3 用户视角设计 > 开发者视角设计

每个新功能默认值应该满足"装完即用"，不要让用户跑额外命令调整才能用上基础体验。
shell completion 这个细节就是经验：第一种设计需要用户主动跑 `kan completion install`，
真用户的反应是"为啥要再输一条命令？"。改成默认自动装 + 环境变量退出之后，
体验立刻就对了。**默认值是产品决策**，不是"先实现再说"。

### 4.4 新功能 = 新测试

不是"觉得不需要"的判断题。每加一条新逻辑路径，对应至少一个测试用例：
功能正常路径 + 至少一个失败/边界路径。
回归（spinner 不显示、跨板块 amount 单位、ST 涨跌停日期切换）的代价
都是"加功能时没加对应测试"。

### 4.5 隐私红线一字不让

公开输出全部走中性词（"用户" / "维护者" / "开发者"），
禁用任何内部别名、内部协作语境、AI 工具署名。
违反这条的代价是**一次性的、不可逆的**——PyPI metadata 改不了，
GitHub commit 即使 rewrite 也会被搜索引擎收录。
所以宁可在 pre-commit 阶段误拦五次，也别让一条内部语境进 main。

### 4.6 数据源不要相信"字段名相同 = 语义相同"

腾讯 `amount` 在不同板块语义不同，akshare 不同接口字段命名不一样，
baostock 字符串需要严格转 numeric。原则：**多源 ETL 必须在 normalize
阶段做语义对齐 + 一致性测试**，不能只做列名映射。本项目用
`_normalize_kline()` 作为所有源的统一出口，并加了 10 条三源一致性测试
（`tests/test_normalize_alignment.py`）。

### 4.7 不要过度抽象

评审中明确否决了一批"看起来很对"的方案：数据源工厂模式、DAL 数据访问层、
独立 API 层、SQLite 替换 parquet、事件总线、全局 trace 开关。
判断标准：**当前痛点没出现就不引入抽象**，遵循熵减优先原则。
4 个数据源的 if-chain 比工厂模式好读；CLI 命令直接读 parquet 比 DAL 简洁；
单进程单写不需要 SQLite。代码体量约 2700 行（含测试），结构平铺、可读。

## 5. 下版方向

按当前路线图（`docs/roadmap.md`）排序，patch 节奏累加：

### 5.1 价格提醒 `kan alert`（最高优先级）

寄生 `kan scan` 数据通路，不另起调度。触发条件：阈值穿越（low/high）、
N 周期位置突破、涨跌幅超阈值。输出走系统通知（macOS osascript / 邮件兜底）。
这是用户最直接缺的能力——目前要靠每天手动跑 `kan scan`。

### 5.2 指数基准对照

自选股扫描时同步给出上证 / 深证 / 创业板 / 沪深 300 的同周期位置。
用于判断"是个股弱还是大盘弱"，避免误判机会。改动小但价值大。

### 5.3 Markdown + JSON 输出（`--format md|json`）

当前只有 terminal table，导出能力缺失。配套推动渲染层抽象
（`render_scan_table()` 拆出来，加 `format` 参数），
为后续 H5 可视化预留接口。

### 5.4 已知技术债（同 patch 节奏修）

- TD-1：parquet 加 `_source` 列（多源缓存来源标注）
- TD-2：熔断器持久化 `circuit.json`
- TD-3：`kan doctor` 命令体检三源 + 代理
- TD-4：baostock 类型转换严格化
