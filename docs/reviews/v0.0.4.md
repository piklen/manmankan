## 4. 取舍

`kan/scanner.py` 保留顶层 pandas。原因是 scanner 内部大量 `pd.DataFrame` 和
`pd.Timestamp` 调用，强行 lazy 化会让核心算法可读性下降。当前入口 spinner 已覆盖
scanner import 成本，用户体感问题已解决。

数据更新进度改写到 stderr，避免未来引入机器可读 stdout 输出时被进度条污染。

## 5. v0.0.5 期望

本次只修启动可见反馈，不优化网络物理耗时。后续可考虑：

- `kan doctor`：诊断数据源、系统代理和缓存状态。
- 持久化熔断器：避免每次启动重复访问短期不可用源。
- K 线缓存写入 `_source`：后续成交量相关分析能按来源判断可信度。
