# 路线图

> 列出**用户面新功能候选**,按优先级分组。优先级 ≠ 发版号,具体哪批 patch 装哪个功能视开发进度而定。
> 版本号遵循 PEP 440 数字 release segment `A.B.C[.D...]`,日常发布保持前三段稳定,只累加维护者明确指定的 patch 尾段。

---

## 用户优先级(产品硬约束)

1. **普通 A 股散户是唯一第一用户**:Web 观察台必须承担安装后的首用、每日查看、自选、持仓、筛选和数据恢复闭环。
2. **AI / 开发者是第二用户**:CLI、JSON、Python API 与 MCP 保持稳定、可审计、可组合,但不主导普通用户的信息架构和首屏。
3. **同一事实只计算一次**:Web、CLI、JSON 和 MCP 复用 service/domain 结果,不分别实现行情计算。

## P0(下一阶段必须验证)

### 1. 普通用户首用闭环

- 首次启动无需理解 CLI、周期参数或数据源,能在 Web 内完成添加自选、录入持仓和首次更新。
- 无数据、数据过期、上游失败时都给出明确原因和下一步动作,不只显示空表或技术错误。
- Windows / macOS / Linux 的安装后提示统一以 `kan web` 为第一动作。

### 2. 每日复看闭环

- 今日页继续聚焦「数据是否最新、发生了什么变化、哪些接近 180 日高低位」三个问题。
- 以真实用户任务验证 30 / 60 / 180 日默认周期、上一份不同交易日快照比较和个股下钻是否足够易懂。
- 建立最小产品指标:安装后成功打开率、首次添加自选完成率、7 日内二次打开率、数据恢复成功率。指标只做本地可选诊断或人工测试,不引入遥测。

### 3. 真实散户可用性验证

- 每个版本至少完成一次全新安装、空数据、已有自选、已有持仓和行情源失败场景验收。
- 收集普通用户最先问的问题,优先修复术语、信息层级和恢复路径,再增加新指标或新数据维度。

---

## P1(P0 闭环稳定后启动)

- **价格提醒**:复用 scan 数据通路提供本地阈值穿越提醒,先验证用户是否需要,再决定通知渠道和调度方式。
- **行业 / 指数对照增强**:在现有指数位置基础上,补充板块维度的位置聚合与下钻,帮助用户区分个股和整体环境。
- **Web 条件筛选增强**:继续使用普通用户能理解的中文条件,高级 DSL 和等价 CLI 保持折叠展示。
- **AI JSON 契约稳定化**:保持 `scan` / `info` / `find` / `history` 等 JSON 顶层 disclaimer、错误 envelope、字段向后兼容,让外部 AI 能低 context 成本消费结构化数据。
- **数据组合边界**:继续增强 CLI / JSON 数据过滤能力,但不内置财报解读、分红日历或策略 preset;需要完整基本面研究时,用 `kan find --format json` 与外部公告 / 财报 / 分红数据源组合。
- **MCP Server 增强**:当前已提供 stdio MCP、本机 Streamable HTTP endpoint 和用户级客户端注册;下一步补更完整的 HTTP 客户端接入样例。设计原则:一个 MCP tool 对应一个复合查询,而非一个 API endpoint 映射一个 tool——减少 Agent 的多次往返。
- **Skills.md 持续同步**:命令变更时同步更新 `skills/manmankan-skill.md`,确保 AI Agent 读到的是当前版本的能力清单。

---

## P2(远期)

- **Source 接口抽象**:提取数据源适配层(Source / DataProvider 接口),为多市场支持打架构基础。
- **多市场扩展**:在 Source 接口稳定后,实现首个非 A 股市场 Source(目标:美股,通过 yfinance 等免费数据源)。"当前专注 A 股,架构为多市场设计。"
- **AI / Agent 增量能力**:只有在不挤占普通用户主路径、且存在真实接入需求时,再扩展更复杂的自动化协议。

---

## 不在路线图(明确不做)

- **实时行情推送** —— CLI 工具不适合,用 broker app。
- **AI 选股建议 / 自动荐股 / 评级 / 信号订阅** —— 合规红线；AI 可以消费 JSON 数据做后续研究,但工具不输出决策结论。
- **多账户体系 / 云同步** —— 单机工具不需要。
- **独立移动端 App** —— 先把现有本地 Web 做到手机浏览器可用,不维护第二套客户端。
- **个股目标价 / 涨跌预测** —— 不在能力边界,也不在使命范围。
- **分红登记日 / 除息日 / 派息日历** —— 当前只提供 `dv_ttm` 股息率裸值;具体分红流程以公司公告 / 交易所数据源为准。
- **`kan doctor` 诊断命令** —— 网络 / 数据源问题在 issue 中按需排查,不进核心 CLI。
- **社交分享 / 一键发帖** —— 偏离工具核心(本地数据扫描),不在使命范围。
- **买入区间 / 买点分档输出** —— 滑向买卖信号(违反「位置 ≠ 买卖信号」),且信息密度过载。
- **思考深度档位(如 `--depth` 多档分析)** —— 借自 LLM 分析类工具的概念;本工具是确定性位置 / 数据扫描,无「思考」环节,该参数无意义。
