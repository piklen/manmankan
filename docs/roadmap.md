# 路线图

> 当前能力与下一阶段候选。优先级不等于发版号；日常版本保持 PEP 440 前三段稳定，只累加 patch tail。

## 已完成：vNext 选股研究闭环

- `kan web` 默认进入 React + TypeScript Screen 工作台；Python 同源托管预构建资产，安装运行不需要 Node。
- `Screen / ScreenRun / CandidateList / CompareSet` 四个领域对象已经落地。
- 支持自选、持仓、全市场、行业、题材和自定义代码池；27 类条件、AND / OR、多排序、结果列、缺失与新鲜度策略。
- 规则保存、内容版本、历史恢复、不可变运行、证据、覆盖率、相邻运行新增/移出/排名变化已经贯通。
- 候选池支持人工状态、备注、来源运行、重命名和删除；规则重跑不覆盖研究状态。
- Web、CLI、公开 Python API、`/api/v1` 和 MCP 共用 `ScreenSpec → ScreenRun` application service。
- OpenAPI 生成 TypeScript 类型；旧 Jinja 和手写业务 JavaScript 已删除。
- 工作台关系状态使用 SQLite WAL；旧配置、自选、持仓和现金可备份迁移、幂等重跑和导出回滚。
- Screen 与行情刷新任务持久化，支持 `queued / running / succeeded / partial / failed / interrupted` 和 SSE。
- 行业/题材趋势、最新成员结构、跨日事实复看和板块原生指数历史事件复核已经贯通 Web 与 typed application service；历史复核不使用当前成分股重造过去。

## P0：真实使用质量

### 0. CLI / AI 研究事实链

- 已新增 `ResearchRequest → ResearchBundle` 与 `kan research` / `kan_research` / Python API。默认市场、估值、财务，其他维度按需；包内逐项保留日期、单位、来源与缺口，不包含模型判断。
- 财务已保留公告日和来源检查时间，24小时缓存与 `--refresh` 共用现有数据服务；研究维度独立取数，不再要求行情基线。
- 后续优先补齐历史前复权基准一致性与其他维度时效；已有证据包装不能代替数据修复。
- 下一条数据主线是有原文与时间的公司/财务/事件研究材料，同时贯通现有候选与复看；按真实问题逐项接入和验证。
- 模型接入先验证实际研究任务的取数、引用、纠错与成本，再增加可恢复会话。现有模块化 Python 核心、SQLite、Parquet 和按需 Web 图表继续复用；多市场、独立 AI 服务和运营平台后置。

### 1. 规则与结果可理解性

- 用真实日常任务验证“股票池 → 条件 → 排序 → 结果 → 证据”是否无需文档即可完成。
- 优先修术语、空状态、错误恢复、窄屏操作和证据层级，不以继续增加指标掩盖交互问题。
- 继续核对 Web、CLI、Python、HTTP 与 MCP 对同一 Screen 的候选、排序、哈希、覆盖率和错误语义。

### 2. 数据完整性与复现

- 扩大真实全市场样本，验证陈旧、部分字段缺失、停牌、新股、北交所和 provider 降级路径。
- 保持 `null ≠ 0`、数据日期、来源、公式版本和 coverage 可见；不允许 UI 用占位值制造完整性。
- 对需要历史研究的场景先补 point-in-time 数据证据，再谈回测或规则效果比较；不拿今天的财务截面重造过去。

### 3. 安装与迁移可靠性

- 每个公开版本继续验证三平台 fresh install、无 Node 启动、空数据、旧 JSON 迁移、迁移后修改和真实回滚。
- SQLite schema 只做向前迁移；无法安全读取更高版本时明确停止，不让旧程序误写。

## P1：选股工作流增强

- **规则导入/导出体验**：在现有 canonical JSON 之上补 Web 导入导出和冲突预览，不引入第二种规则格式。
- **运行复看增强**：按数据日和字段变化展开 diff，保持证据可追溯，不生成方向性结论。
- **候选研究结构化**：把自由备注扩展为可选的“待验证事实 / 来源 / 下次重看条件”，仍由用户决定状态。
- **对比数据按需补齐**：为缺失指标提供显式取数动作和成本预览，不在打开页面时静默发起高成本网络请求。
- **任务恢复体验**：在持久状态之上提供重试入口和更细水位展示；当前已经落盘的缓存必须继续复用。
- **API 契约稳定化**：根据真实消费者反馈冻结 `/api/v1` 兼容策略，再决定何时移除隐藏的旧 `/api`。

## P2：AI 与多市场

- **可选 AI provider adapter**：只有在真实接入需求成立后，让模型把自然语言整理为 typed Screen proposal；所有模糊阈值、假设和 plan diff 必须可见，确认后仍由确定性 application service 执行。
- **证据约束解释**：AI 输出只能引用已存在的 `evidence_ref`；增加 provider 不得形成第二套指标或筛选内核。
- **市场级 Source**：在现有 Kline/Metrics provider contract 上补市场路由，再实现首个非 A 股 Source；不同市场不共享错误域和不适用字段。

## 明确不做

- 券商下单、自动交易、条件单、分钟级交易终端或信号订阅。
- 隐藏权重综合评分、默认“最佳标的”排序、模型生成的金融事实或无法展开的 AI 结论。
- 个股目标价、涨跌预测、仓位动作或买卖动作输出。
- 多账户 SaaS、云同步、社交分享、团队协作或独立移动端 App。
- 为单机工作台引入 Postgres、Redis、Celery、GraphQL、Electron、Tauri 或 Kubernetes，除非真实瓶颈证明当前架构无法达标。
- 在没有 point-in-time 数据证据时宣称历史回测、规则收益或可复现的过去截面。

## 版本节奏

- patch tail 可以承载当前兼容范围内的完整功能批次。
- minor / major / epoch 只在维护者明确批准且 breaking 影响已说明时变化。
- 合并 main 不等于发布 PyPI 或 GitHub Release；公开发布仍需要单独授权和验证。
