# 慢慢看 · 合规红线

> 开发者贡献代码时,所有用户可见输出必须过本文件的红线检查。
> `kan find` 与 vNext Screen 的所有选股相关代码额外过 §7 检查。

---

## 1. 红线(不得触碰)

- 推荐具体股票买卖
- 预测涨跌 / 给出目标价
- 给出"建议买入 / 卖出"标签
- 提供"AI 选股建议"、自动荐股或托管决策
- 文案出现以下关键词

## 2. 安全区

- 展示客观行情数据(OHLCV)
- 展示用户自定义的筛选结果
- 输出结构化 JSON 供用户或 AI 做后续研究 / 筛选
- 提供技术指标计算工具
- 用户自行设置的价格预警
- 展示用户录入的持仓事实及其算术衍生值(市值 / 仓位 / 今日盈亏 / 累计盈亏)
- 展示散户体验事实:一手金额、占已录入现金比例、科创 / 北交 / 创业板权限提示、距区间高低点距离、量价方向组合
- 措辞:"60 日最低 / 触及 30 日低点 / 价格位于 90 日区间下沿"

## 4. 命名约定

- **品牌名**:慢慢看(避开"买"字 · 不暗示行为)
- **目录名**:`manmankan`(拼音)
- **筛选命令**:`kan find`(中性 · find = 查找)· 输出"符合条件的股票"· 禁 `pick/select/推荐/优选`
- **持久规则**：`Screen` 表示用户定义的筛选规则，`ScreenRun` 表示该规则在特定数据上的运行事实；不得把对象名或运行状态写成产品判断。

## 5. 强制文案

每次 CLI 输出底部 / 每个 Web 页面 footer 必带:

> **创新低 ≠ 见底 · 创新高 ≠ 顶 · 历史价格不预示未来 · 仅供参考,不构成投资建议**

`kan find` 输出末尾追加:

> **候选 ≠ 买入信号 · 工具仅返回符合您设置规则的股票数据 · 不构成任何形式的推荐或建议**

`kan hold` 输出末尾追加:

> **持仓的客观坐标 + 盈亏事实 · 不构成买卖建议**

## 6. 合规定位

本工具严格定位为**行情数据展示工具**及**用户主导的数据筛选工具**,可作为人或 AI 的研究输入,但不包含买卖建议、评分评级、策略推荐等任何投资指导性质的功能。位置 / 共振使用日 K 数据；持仓盈亏在盘中可使用免费实时价,但只服务现价口径的盈亏计算。输出是经中性化的事实,不是行情解读；理解数据含义与后续决策由用户负责。

## 7. 选股器（`kan find` / `kan screen`）合规细则

`kan find` 和 Screen 是**用户主导的条件筛选器**，不是 AI 推荐、策略库或信号订阅。Screen 只增加保存、版本、运行证据、diff、候选研究和比较，不改变规则来源边界：

新建 Screen 不得预置可直接运行的条件组合、排除范围或排序；至少由用户添加一个条件或选择一个排除项后才允许保存/运行。输入控件可以提供可编辑起始值，但必须完整可见，不得伪装成系统结论。

| 边界 | 允许 | 禁止 |
|---|---|---|
| 规则来源 | 用户显式指定 filter / 自定义代码池 | 内置 preset · 推荐组合 · 默认策略 |
| 评估 | 数据原始值(代码/名称/位置/一手金额/权限提示/量价方向/估值/质量/资金/技术/情绪/筹码) | 评分 · 评级 · 综合得分 · 超买超卖/金叉死叉等信号判断 |
| 输出 | "符合条件的股票"列表、覆盖率、证据、diff、用户候选状态 | "推荐/值得关注/优选" 等 |
| 触发 | 用户主动跑命令 | 定时调度 · 邮件/消息推送 |
| 商业 | 代码按 AGPL-3.0 使用；修改 / 网络服务 / 二次分发的源码义务、数据源条款和投顾合规另行遵守 | 把本工具包装成荐股、投顾、托管决策或信号订阅服务 |
| AI 接入 | typed parse/plan/run/get/explain；只整理明确阈值、执行确定性服务、引用已有 evidence | 内置或托管 LLM 自行定阈值、重算候选、生成金融事实或输出 AI 选股建议 |
| Disclaimer | 本项目输出按 §5 强制 · 测试守护 | 用户关闭 · 删除或弱化公开输出风险提示 |

估值 / 质量 / 资金 / 技术 / 情绪 / 筹码 / 股东持股指标（PE/PB/ROE/增速/主力净额/RSI/MACD/KDJ/连板/获利盘/户数环比/前十大集中度/北向占比）按用户显式 filter 输出原始值。Screen 可按用户明确选择的最多三个裸字段排序；不评分、不评级、不使用隐藏权重或默认“最佳标的”顺序。

板块榜单(`kan board rank`)只按用户选择的客观字段排序(主力净额 / 区间涨幅 / 位置百分位),不输出板块强弱判断、轮动结论或买卖动作。`--codes` 自定义池只改变候选范围,不改变筛选规则来源:规则仍必须由用户显式输入。

**技术 / 情绪 / 筹码指标特别守则**:filter 用裸值阈值(`--rsi lt:30` 用户主导阈值)· **不内置金叉/死叉等信号 preset**(金叉=买入是信号订阅 · 踩本节红线)· 输出 RSI/MACD/连板数等原始值让用户自判 · **不输出「超买 / 超卖 / 金叉 / 死叉 / 强势 / 妖股」判断词**(§3 黑名单延伸)。金叉/死叉本质需跨日对比(截面单日只有当日值)· 工具只做裸值阈值不做信号。连板数据(`limit_list_d`)不含 ST 股(接口本身不统计 ST)。

**股东持股特别守则**:filter 用裸值阈值(`--top10 gte:50` 用户主导)· 股东户数环比 / 前十大流通集中度 / 北向持股占比是**已披露客观事实的算术衍生**(交易所 / 公司定期披露)· 裸值可出。**不输出「主力建仓 / 洗盘 / 控盘 / 高度控盘 / 锁仓 / 吸筹」等持仓行为判断词**(§3 黑名单延伸 · 持股结构极易被误读为主力意图 · 工具只出占比数字不做行为推断)。数据为**季度披露**(非日频)· `None` = 该期无披露 / 未进前十大流通(非数据故障)。**北向口径降级**:个股北向日频明细(`hk_hold`)2024-08 后停止披露(实测核实)→ `--north` 改用十大流通股东中「香港中央结算有限公司」季度名义持有人占流通比作代理 · 诚实标注为季度级、名义持有人口径(业界通用北向代理)· 未进前十 → `None`。逐股拉取(`stk_holdernumber` / `top10_floatholders`)· 全市场 `--all` 不支持(同 `--roe`)。

## 8. 真实持仓(`kan hold`)合规细则

`kan hold` 是用户手动录入的本地事实账本 · 不是资产管理、投顾或交易指令工具:

| 边界 | 允许 | 禁止 |
|---|---|---|
| 数据来源 | 用户在 Web 或 CLI 主动录入成本、股数、现金 | 读取券商账户、读取外部私有文件、自动推断持仓 |
| 计算 | 现价、市值、仓位、今日盈亏、累计盈亏、30/60/180 日位置 | 基于持仓状态输出交易动作、处置结论或策略标签 |
| 体检 | "3 只在高位"、"2 只浮亏"、"总仓位 60%" | "高位需注意"、"浮亏应处理" 等带动作暗示的措辞 |
| 风险提示 | 除权除息后提醒用户核对成本 / 股数 | 自动调整成本 / 股数或替用户解释行为含义 |
| 隐私 | XDG 本地 `workspace.sqlite3`、迁移备份、`0600`、`--mask` | debug 日志输出成本、股数、现金或账户总额 |

持仓功能的核心输出只能是**客观坐标 + 盈亏事实**。金额口径首版按裸价差计算,不计佣金 / 印花税；当日建仓或昨收缺失时今日盈亏显示为空值。任何 `scan` / `find` 因持仓池增加的标记只能表示来源(`💰`),不能改变排序、筛选规则或输出结论。
